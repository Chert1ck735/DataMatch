# Входные данные и локальные результаты

Проект использует данные организаторов DATA MATCH. Исходные файлы, модели, промежуточные таблицы
и оценки отдельных игроков не входят в публичный репозиторий. Для запуска нужны локальные файлы
в исходной схеме организаторов; конвейер не скачивает набор данных автоматически.

## Файлы

| Каталог | Файл | Назначение |
|---|---|---|
| `paths.data_dir` | `events.parquet` | События обучающих матчей |
| `paths.data_dir` | `games.csv` | Справочник обучающих матчей |
| `paths.data_dir` | `players.csv` | Справочник игроков |
| `paths.data_dir` | `player_teams.csv` | Связи игроков с командами |
| `paths.data_dir` | `teams.csv` | Справочник команд |
| `paths.data_dir` | `rink_geometry.csv` | Геометрия площадок в метрах |
| `paths.test_dir` | `events_test.parquet` | События тестовых матчей |
| `paths.test_dir` | `games_test.csv` | Справочник тестовых матчей |
| `paths.test_dir` | `player_seasons_test.csv` | Сезонные сведения об игроках теста |
| `paths.test_dir` | `players_new.csv` | Дополнительные игроки тестовой выборки |

Список файлов и функции чтения определены в [src/datamatch/io.py](../src/datamatch/io.py).
Среди полей событий: идентификатор матча `match_id`, порядок `seq`, тип `event_type`, участники
`actor_id` / `other_id`, команды, период и время `period` / `clock_s`, зона и координаты,
численность `n_home` / `n_away`. Точные имена читаемых полей перечислены в `EVENT_COLS`.
События состава и смен интерпретируются слоем L0; произвольная таблица play-by-play потребует адаптации.

## Настройка путей

В [configs/default.yaml](../configs/default.yaml) по умолчанию указано:

```yaml
paths:
  data_dir: ../DataMatch_Аналитический_трек/data
  test_dir: ../DataMatch_Аналитический_трек/data/test
```

Можно изменить эти два значения или скопировать **весь** конфиг в `configs/local.yaml`
и передавать `--config configs/local.yaml` в CLI и поддерживающие этот флаг скрипты.
Частичный YAML не объединяется с конфигурацией по умолчанию.
`configs/local*.yaml` исключены из Git, чтобы локальные пути не попадали в репозиторий.
Скрипт `run_tier_a.sh` читает `configs/default.yaml`.

Относительные пути всегда разрешаются от корня проекта, в том числе при использовании другого файла
конфигурации. Абсолютные пути поддерживаются. Конвейер читает исходные файлы без их изменения.

## Производные файлы

- `cache/` — промежуточные таблицы и модели, включая реплики бутстрэпа;
- `artifacts/` — выбор моделей, разбиения, реестр и отчёты по слоям;
- `outputs/` — рейтинги игроков, карточки и аналитические отчёты;
- `logs/` — журналы выполнения;
- `runs/` — сохранённые материалы отдельных экспериментов и сравнений.

Эти каталоги исключены из Git. Агрегированные результаты исходного исследования приведены
в [RESULTS.md](RESULTS.md). Файлы с индивидуальными оценками создаются локальным расчётом.

Ключи кэша учитывают SHA-256 исходных файлов, конфигурацию и исходный код.
После изменения данных или параметров устаревший кэш не должен подменять новый расчёт.
Подробности — в [архитектуре](ARCHITECTURE.md) и разделе 9 [методики](METHODOLOGY.md).
