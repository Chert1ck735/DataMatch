# DATA MATCH — оценка вклада хоккеистов по событиям матча

**Задача проекта — по событиям хоккейных матчей оценить, насколько действия каждого полевого игрока
с шайбой помогают команде создавать голевые моменты и мешать сопернику, и показать надёжность этой оценки.**

Голы и передачи отражают лишь часть полезных действий. Игрок может регулярно продвигать шайбу,
создавать опасные атаки и возвращать владение, но набирать мало очков. Другой — иметь столько же очков,
но чаще терять шайбу и отдавать инициативу сопернику. Аналитику клуба важно увидеть эту разницу
и понять, какие игроки и стороны их игры заслуживают подробного разбора по видео.

Проект переводит действия с шайбой в общую числовую шкалу: оценивает, как пас, бросок, потеря или отбор
изменили ожидаемую разницу голов, затем суммирует вклады игрока с учётом времени на льду.
Результат — **рейтинг относительно среднего игрока своего амплуа**, профиль сильных и слабых сторон,
95%-интервал и метка надёжности. Это позволяет отличать подтверждённый вклад от оценки по малому числу матчей.

Вход — журнал событий матчей, сведения об игроках и командах, составы и смены.
Выход — таблица оценок и карточки игроков с объяснением результата.
В реализованном исследовании оценены **568 полевых игроков в 84 тестовых матчах «Авангарда» сезона 2025/26**,
включая игроков соперников. Модели обучены на отдельной выборке матчей.

**В репозитории:** исходный код, конфигурация, тесты, ноутбук воспроизведения и методика.
Исходные данные, обученные модели, кэши и таблицы с оценками игроков не публикуются и исключены из Git.
Начните с [результатов](docs/RESULTS.md) и [архитектуры](docs/ARCHITECTURE.md);
для полного расчёта нужны локальные данные организаторов.

## Возможности

- Подготовка событий, составов на льду, смен и времени игроков.
- Выбор модели вероятности гола при броске (xG) и модели ценности игровой ситуации.
- Распределение изменения ценности между участниками действий.
- Профиль из пяти компонентов: созидание, броски, потери, отборы и вбрасывания.
- Поправка на объём данных с помощью эмпирического Байеса по амплуа.
- Интервалы с учётом неопределённости моделей и карточки игроков с выводами словами.
- Проверка повторяемости, покрытия интервалов и прогноза будущей игры.

## Основные результаты

Числа относятся к сохранённой конкурсной версии A; подробности — в [отчёте](docs/RESULTS.md).

| Показатель | Результат |
|---|---|
| Обучение после проверок качества | 887 матчей, 1,67 млн действий с шайбой |
| Тест | 84 матча «Авангарда», 568 полевых игроков обеих сторон |
| Повторяемость рейтинга на половинах матчей¹ | **0,60 [0,51; 0,67]** |
| Повторяемость очков за 60 минут¹ | 0,34 [0,20; 0,45] |
| Покрытие результата другой половины матчей 95%-диапазоном | 94,6% |
| Сходство рейтингов при расчёте на другой машине | корреляция Спирмена 0,996 |
| Прогноз будущей игры | убедительное улучшение не показано |

¹ Корреляция с поправкой Спирмена–Брауна; в скобках — 95%-интервал.
Покрытие результата другой половины и интервал скрытого уровня игрока — разные проверки;
подробности приведены в [методике](docs/METHODOLOGY.md).

## Как устроен расчёт

```text
L0  Подготовка событий, смен, времени на льду и разбиений
 ↓
L1  Вероятность гола при броске — xG
 ↓
L2  Ценность игровой ситуации — V(s)
 ↓
L3  Вклады отдельных действий — δ
 ↓
L5  Поправка на объём данных — эмпирический Байес
 ↓
L6  Итоговый рейтинг, интервалы и надёжность
 ├─ Карточки игроков и сводка для клуба
 └─ L7: проверка повторяемости, прогноза и покрытия
```

В итоговой версии используется монотонный LightGBM для xG и калиброванная марковская модель
ценности ситуации. RAPM (L4), поправка на партнёров и соперников, реализован как эксперимент,
но не включён в итоговый рейтинг: он не прошёл критерий повторяемости.

**Стек:** Python 3.12, NumPy, pandas, PyArrow, SciPy, scikit-learn, LightGBM, CatBoost,
InterpretML, Optuna, pytest и Hypothesis. Расчёт выполняется на CPU.

## Установка и запуск

Команды выполняются из корня проекта и рассчитаны на Linux/macOS. Для полного расчёта ориентируйтесь
на 16 ГБ ОЗУ и несколько часов работы CPU. Бутстрэп L6 с 200 репликами может занять большую часть времени.
Параллелизм задаётся в `bootstrap.n_jobs` и `bootstrap.replicate_workers` в конфигурации.

### 1. Окружение

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
export PYTHONPATH=src
```

`requirements.lock.txt` фиксирует версии для воспроизведения исходного расчёта.
`requirements.txt` содержит прямые зависимости без фиксации версий; установка из него создаёт другое
окружение и может изменить результат выбора моделей.

### 2. Данные

Разместите файлы организаторов локально и укажите `paths.data_dir` и `paths.test_dir`
в [configs/default.yaml](configs/default.yaml). По умолчанию ожидается каталог
`../DataMatch_Аналитический_трек/data` рядом с проектом, тестовая часть — в его подкаталоге `test/`.
Относительные пути отсчитываются от корня проекта; абсолютные тоже поддерживаются.
Список файлов и настройка отдельного локального конфига — в [описании данных](docs/DATA.md).

### 3. Полный расчёт

```bash
sh scripts/run_tier_a.sh full
```

Скрипт выполняет L0 → L1 → L2 → L3 → L5 → L6, проверки L2, внешний аудит, правило отображения
надёжности и расчёт карточек. Статус — в `logs/tier_a.status`, журналы этапов — в `logs/tier_a.*.log`.
Повторный запуск использует актуальные кэши и продолжает расчёт.

Для запуска этапов по отдельности:

```bash
.venv/bin/python -m datamatch.cli prepare
.venv/bin/python -m datamatch.cli xg
.venv/bin/python -m datamatch.cli value
.venv/bin/python -m datamatch.cli contrib
.venv/bin/python -m datamatch.cli shrink
.venv/bin/python -m datamatch.cli ratings --mode full
.venv/bin/python scripts/apply_display_rules.py --mode full
.venv/bin/python scripts/apply_display_rules.py --mode full --check
```

`ratings --mode fast` использует 30 реплик вместо 200 и пишет `outputs/test_ratings_fast.csv`.
Это отладочный режим, который всё равно требует готовых предыдущих слоёв.
Для пошагового расчёта с аудитами и карточками используйте [ноутбук](notebooks/reproduce_ratings.ipynb).

Отчёт проверки рейтинга строится отдельно после L5:

```bash
.venv/bin/python scripts/validation_report.py
```

CLI поддерживает `--config путь/к/config.yaml`, `--force` для пересчёта этапа и `--force-all`
для пересчёта с предыдущими слоями. Команды `contrib`, `shrink` и `ratings` требуют готовых входов:
запускайте их в указанном порядке. Скрипт `run_tier_a.sh` использует конфигурацию по умолчанию.
Коды выхода CLI: `0` — успех, `2` — провал проверки качества, `3` — занят кэш,
`4` — не готов вход предыдущего слоя.

## Результат расчёта

Основной файл — `outputs/test_ratings.csv`, одна строка на полевого игрока тестовой выборки.

| Поле | Значение |
|---|---|
| `player_id` | Идентификатор игрока из исходных данных |
| `role` | Амплуа: `C` — центр, `W` — крайний, `D` — защитник |
| `rating` | xG за 60 минут относительно среднего своего амплуа; 0 — средний уровень |
| `lo95`, `hi95` | Границы 95%-интервала оценки |
| `reliability` | `HIGH`, `MEDIUM` или `LOW`; при времени на льду менее 60 минут всегда `LOW` |
| `toi_min`, `games` | Время на льду в минутах и число матчей |

Если интервал целиком выше или ниже нуля, отличие от среднего амплуа подтверждено в рамках модели.
Если он пересекает ноль, данных недостаточно для такого вывода. Надёжность показывает, насколько
оценка опирается на собственные данные игрока.

Рядом сохраняются:

- `outputs/test_ratings_detail.csv` — компоненты и детализация неопределённости;
- `outputs/test_ratings_meta.json` — параметры, статус и SHA-256 результата;
- `outputs/card/club_ratings.csv` — перцентиль в амплуа, надёжность и вывод словами;
- `outputs/card/card_report.md` — сводный отчёт по карточкам;
- `outputs/validation_report.md` и `.json` — отчёт проверки после отдельного запуска.

Карточки дополняют рейтинг отдельными показателями: роли и похожие игроки, игра в разных составах,
удаления, вбрасывания, WAR и физический профиль с шайбой. Текст собирается детерминированными шаблонами.

## Проверки кода

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
sh scripts/check_quality.sh
```

Скрипт запускает Ruff, проверку компиляции Python и pytest; в Git-репозитории также проверяет
ошибки пробелов в diff. Отдельный запуск тестов: `.venv/bin/python -m pytest -q tests`.
Часть интеграционных тестов требует локальных исходных данных.

## Ограничения

- Рейтинг описывает действия с шайбой. Игра без шайбы и влияние звена видны лишь частично:
  непрерывного трекинга нет, RAPM в итог не включён.
- Сравнение ведётся относительно своего амплуа. При малом времени оценки сильнее стянуты к среднему.
- Интервалы зависят от допущений модели и рассчитаны относительно оценённого среднего амплуа.
- Перенос между лигами и сезонами не валидирован отдельно: train охватывает 2018–2023 годы, test — 2025/26.
- Убедительное улучшение прогноза будущей игры не показано. Рейтинг служит основанием для дальнейшего
  просмотра игрока вместе с видео и контекстом команды.
